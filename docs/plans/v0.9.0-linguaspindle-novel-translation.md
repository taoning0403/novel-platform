# 漫读 v0.9.0 凭证能力、贡献者馆藏与 LinguaSpindle 小说翻译开发指令

> 本文件是一份后续开发 Agent 可直接执行的规划指令，不代表当前仓库已经实现
> v0.9.0。只有用户明确要求“按本指令执行”后，才开始代码、迁移、测试、提交或部署。

## 一、目标与执行顺序

v0.9.0 同时完成三项相互依赖的调整：

1. 删除两个无文件占位入口及其公开 API：
   - 书库页的“高级：仅创建空 Book”；
   - Book 详情页的“仅添加无文件 Edition（兼容旧流程）”。
2. 把固定“只读”的受邀人凭证扩展为管理员在签发或重新签发时选择的能力凭证：阅读、
   上传、使用小说翻译。
3. 通过 Novel Platform Server 接入已部署的 LinguaSpindle v0.3.1，让管理员以及持有翻译
   能力的受邀人发起翻译、重翻并管理自己的任务。

同时把“站点馆藏 owner”和“内容贡献者”拆开：站点仍由唯一管理员管理，但每本 Book、
每个 Edition、上传文件和翻译任务都记录实际创建者。作品显示上传人；受邀人创建的小说或
生成译本，只能由该受邀身份或管理员删除。

本版本允许破坏性变更。站点未进入 1.0 且没有实际用户，因此不为无文件占位流程、旧 API
客户端或现有调试数据增加兼容层。破坏性权限不等于可无审计删除远端资源：实际迁移和部署
仍须先盘点、备份，并停在本文件规定的审批点。

执行顺序：

1. 重新核对 Git、v0.8.0 验收、PostgreSQL 数据和服务器部署基线。
2. 先新增 ADR，固定凭证能力、贡献者归属、删除矩阵和 LinguaSpindle 边界。
3. 完成破坏性迁移、服务端能力校验和贡献者策略。
4. 开放受控的文件型上传，并移除空 Book/Edition 契约。
5. 实现 Translation Run、私网客户端和生成 Edition 原子导入。
6. 实现 Quiet Trace Web、验收、备份/恢复和部署资料。
7. 本地验收后停在发布审批点；未经单独授权，不推送、不打 tag、不迁移服务器、不部署。

## 二、执行前必须重验的基线

规划时已经核对：

- Novel Platform 当前维护基线为 v0.8.0：唯一管理员拥有站点馆藏，受邀人只能读取
  `ready` 且带当前文件的 Edition。
- `reader_access_credentials` 当前只有生命周期、有效期和设备策略，没有 capability、
  permission 或 scope；每个受邀身份最多一份未撤销的当前凭证。
- 每个受保护请求都会重新加载 Session、User、Device 和凭证，因此数据库可以继续作为
  能力权威，无需信任 JWT 内的陈旧权限。
- `LibraryAccessService.require_manager()` 当前把上传、导入、Book/Edition 修改与删除都
  锁给管理员。
- `books.owner_user_id`、`stored_files.owner_user_id`、`library_imports.owner_user_id`
  代表唯一管理员馆藏 owner；`book_editions` 没有创建者字段。
- `POST /api/v1/books` 和 `POST /api/v1/books/{book_id}/editions` 当前可创建无文件对象；
  Web 分别由 `CreateBookForm`、`EditionCreateForm` 调用。
- 文件上传已有 inspect → preview → commit，支持 EPUB/TXT、新建 Book、添加 Edition 和
  替换文件，并已有事务与物理文件补偿。
- 当前 Book/Edition 删除只允许管理员，物理文件由 `LibraryFileService` 按引用精确清理。
- 当前已有 `translation + ai + generated`、source/supersedes 链和 draft/ready/archived，
  但没有 Translation Run。
- 已引用部署记录表明 LinguaSpindle annotated `v0.3.1` tag 指向
  `4410cd3c33089abef7146979f8ad39fad0efdc78`，容器别名为 `linguaspindle`，网络为
  `linguaspindle-private`，容器监听 8765，宿主机没有发布该端口。
- 已引用验收确认 v0.3.1 health、OpenAPI、强制 `Idempotency-Key`、428 和
  `X-Request-ID`；当次部署没有配置真实 Provider Key。

执行 Agent 必须重新 `git fetch`、核对 refs、迁移 head、LinguaSpindle tag/镜像和只读在线
状态；本节是导航快照，不是实时证据。

## 三、破坏性兼容边界

### 3.1 删除无文件占位能力

从 v0.9.0 起，新 Book/Edition 只能来自：

- 通过校验的 EPUB/TXT inspect/commit；或
- LinguaSpindle 成功生成并经校验导入的翻译文件。

必须：

- 删除两个截图中的 legacy Collapse，不留空白占位或隐藏开关。
- 删除 `CreateBookForm.tsx`、`EditionCreateForm.tsx` 及只为它们存在的状态、样式和测试。
- 从 Web client 移除 `createBook`、`createEdition`。
- 删除公开的两个 metadata-only POST 及其公开 request schema。
- 保留 `BookService.create`、`EditionService.create` 等内部能力，供原子 import/generated
  ingestion 使用；不得复制创建逻辑。
- 不提供兼容 flag；旧 POST 返回 404/405，不能再产生无文件行。

### 3.2 迁移可以清理占位数据

新的 Alembic migration 允许：

1. 删除没有任何 `edition_files` 的 BookEdition。
2. 删除因此不再包含任何文件型 Edition 的空 Book。
3. 清理对应偏好、进度和关系；物理文件仍通过现有引用检查与补偿机制精确处理，禁止 SQL
   按路径或通配符删文件。
4. 将保留内容的新贡献者字段回填为 `site_settings.library_owner_user_id`。

迁移前只读统计待删/保留数量。站点未完成 v0.5 转换、没有唯一 owner、存在活动 import 或
文件引用异常时必须 fail closed，不能猜 owner。

历史 v0.1–v0.8 脚本和证据作为历史保留，不重写旧报告伪装兼容。v0.9 不再承诺空
Book/Edition 行为；旧门禁若依赖该行为，应在 v0.9 报告中明确标为被新产品决策取代。

### 3.3 可选开发环境 reset

若审计证明全部是可丢弃调试数据，可提供显式 reset runbook，但必须：

- 写明精确 Compose project、PostgreSQL volume 和 library volume；
- 先生成可验证备份与清单；
- 只在用户另行批准具体远端目标后执行；
- 不触碰 LinguaSpindle 的 SQLite、Artifact Volume、容器或网络；
- 完成后重建管理员和测试凭证并跑 v0.9 全量验收。

reset 不能成为启动或 Alembic 的隐式副作用。

## 四、凭证能力模型

### 4.1 能力集合

| 能力 | 签发规则 | 授权 | 不授权 |
| --- | --- | --- | --- |
| `library.read` | 每份受邀凭证强制包含 | 读取 ready 馆藏、写自己的阅读状态 | 上传、删除、翻译、管理他人内容 |
| `library.upload` | 管理员可选 | 文件型上传，管理/删除自己的上传内容 | 翻译、Series、发布生成译本、管理他人内容 |
| `translation.use` | 管理员可选 | 翻译可读 TXT，管理自己的 Run/生成译本 | 任意上传、他人 Run、Provider 配置、发布 |

签发 UI 中 `library.read` 已选且不可取消。若需完全禁止访问，应暂停或撤销凭证。

唯一管理员不使用 ReaderAccessCredential；正常 Passkey Session 具有全部有效能力。
Recovery Session 不得获得任何馆藏或翻译能力。

`translation.use` 可让内部流程生成 Edition，但不隐含 `library.upload`。因此“阅读 + 翻译”
用户能翻译可读原文，却不能上传任意 EPUB/TXT。

### 4.2 能力属于 Credential，归属属于 User

- 能力是 `reader_access_credentials` 的不可变签发快照，不存到 User，不编码进 raw
  credential，不以 JWT claim 为授权权威。
- 建议新增 `reader_credential_capabilities`，以 `(credential_id, capability)` 为复合主键。
- 为所有保留的受邀凭证回填 `library.read`，不得自动授予 upload/translate。
- 初次签发和 reissue 提交能力集合；服务端强制 read，拒绝未知、重复能力。
- 能力不能原地 patch。升级/降级必须 reissue；旧凭证、Devices、Sessions、Refresh Tokens
  按现有规则立即撤销，新 raw credential 只显示一次。
- 每个保护请求重新加载 Session 绑定凭证及能力。前端缓存、role、JWT 不能替代该检查。
- 内容归属关联 durable User。凭证轮换不转移内容；暂停/撤销让 User 暂时失去操作能力，
  但 attribution 保留，管理员始终可管理。

### 4.3 授权必须有两层

第一层检查当前会话：管理员，或 `require_capability(library.upload)` /
`require_capability(translation.use)`；Recovery Session 一律拒绝。

第二层检查资源：

- 当前 User 是否为 Book/Edition/Run 创建者；
- 资源是否属于当前站点 library owner；
- 状态、依赖、活动任务和文件引用是否允许动作。

路由 dependency 与 application service 都检查。响应提供服务端计算的 permission flags，
Web 不得靠 role 或公开 contributor ID 猜权限。

## 五、馆藏 owner、贡献者和删除规则

### 5.1 数据模型

现有 `owner_user_id` 继续表示唯一管理员站点馆藏 owner，用于隔离、文件完整性、备份和
Series；它不再被解释为“上传人”。

新增非空字段：

| 实体 | 字段 | 语义 |
| --- | --- | --- |
| `books` | `created_by_user_id` | 首次文件型导入创建作品的 User |
| `book_editions` | `created_by_user_id` | 上传或发起生成该 Edition 的 User |
| `stored_files` | `created_by_user_id` | 使该物理对象进入馆藏的 User |
| `library_imports` | `requested_by_user_id` | 发起 inspect/commit 的 User |
| `edition_translation_runs` | `created_by_user_id` | 发起翻译/重翻的 User |

Book 显示 `created_by_user_id` 对应的“上传人”。Edition 按 creation method 显示“上传人”或
“翻译发起人”。只返回安全 `ContributorSummary { display_name }`，不向其他受邀人暴露
username、admin note、User ID、credential hint、存储路径或哈希。

Book/Edition DTO 同时返回服务端计算的 `can_edit`、`can_delete`、`can_upload_edition`、
`can_translate`，避免 Web 自行判断。

### 5.2 操作矩阵

| 动作 | 管理员 | 仅阅读 | upload | translate |
| --- | --- | --- | --- | --- |
| 阅读 ready 内容 | 是 | 是 | 是 | 是 |
| 新建文件型 Book | 是 | 否 | 是 | 否 |
| 向可见 Book 上传 Edition | 是 | 否 | 是 | 否 |
| 替换文件/编辑元数据 | 任意 | 否 | 仅自己创建的资源 | 否 |
| Series、发布状态、原始下载 | 是 | 否 | 否 | 否 |
| 发起 TXT 翻译/重翻 | 是 | 否 | 否 | 是 |
| 查看/控制 Run | 全部 | 否 | 否 | 仅自己的 |
| 删除上传 Edition | 任意 | 否 | 仅自己的 | 否 |
| 删除生成 Edition | 任意 | 否 | 否 | 仅自己的 |
| 删除整本 Book | 任意 | 否 | 自己创建且无他人 Edition/Run | 否 |

同时持有 upload + translate 时取并集，但不获得他人资源权限。

### 5.3 受邀上传约束

- `/upload` 和 imports API 对管理员或 `library.upload` 开放。
- 受邀上传者可 `create_book`、`add_edition`，只能对自己创建的 Edition
  `replace_edition_file`。
- 受邀上传者不能管理 Series、选择 archived、发布生成译本、下载 raw 文件或替换他人文件。
- 普通上传通过校验后沿用当前行为提交为 `ready`；授予 upload 即代表管理员信任该身份向
  私有共享馆藏贡献可读文件。
- Import 按 `requested_by_user_id` 隔离；管理员可管理全部，其他人访问非自己的 import
  返回 404。
- StoredFile 的 `owner_user_id` 仍为站点 owner，实际 actor 写到 `created_by_user_id`；
  不能把受邀人变成第二个 library owner。

### 5.4 删除语义

- 上传 Edition：管理员，或创建者本人且当前凭证仍有 `library.upload`。
- 生成 Edition：管理员，或创建者本人且当前凭证仍有 `translation.use`。
- Book：管理员，或 Book 创建者本人仍有 upload，且 Book 的所有 Edition 与所有保留的 Run
  都是该 User 的贡献；任何活动 Run 仍须先终止并完成可解释的远端清理。
- Book 内出现其他 User 的 Edition 或 Translation Run 时，原上传者整本删除返回
  `409 book_contains_other_contributions`；其仍可逐个删除自己且无依赖的 Edition。
- source/supersedes 依赖、活动 Run 或正在 commit 的 Import 阻止删除；管理员也不能绕过
  数据完整性，须先处理依赖。
- 删除生成 Edition 不删除 Run 历史；`generated_edition_id` 使用可解释的 SET NULL/tombstone。
- 管理员删除整本 Book 时可以在确认后级联删除其终态 Run 历史；活动 Run 必须先终止，且
  任何远端 Project 都只能按持久化的精确 ID 清理。
- 不提供单独按 StoredFile ID 删除的产品接口。删除 Book/Edition 后精确清理未引用文件。
- 删除 ready Edition 会清除所有用户指向它的 preference/progress；确认文案必须说明。
- 可见资源越权写入返回稳定 403；不可见资源继续 404。

管理员撤销 upload/translate 后，历史 attribution 保留，但该 User 暂时不能删除对应内容，
直到重新获得能力；管理员始终可操作。

## 六、LinguaSpindle 服务边界与翻译范围

### 6.1 独立服务

- LinguaSpindle 不依赖 Novel Platform 的数据库、User、Book、Edition、capability 或 Session。
- Web 绝不直连；调用链只能是：

~~~mermaid
flowchart LR
    A["管理员或获授权受邀人"] --> B["漫读 Web"]
    B --> C["Novel Platform FastAPI"]
    C --> D["PostgreSQL"]
    C --> E["私有馆藏 Volume"]
    C -->|"私有网络 HTTP"| F["LinguaSpindle v0.3.1"]
    F --> G["LinguaSpindle SQLite / Artifact Volume"]
    F --> H["服务器配置的外部 Provider"]
~~~

- 两个系统不共享 DB、Volume、存储路径、身份或领域对象。
- 只让 Novel Platform Server 加入 `linguaspindle-private`；Web/Postgres/migrate 不加入，
  不增加 LinguaSpindle 宿主端口。
- Provider Key 只在 LinguaSpindle 环境/secret 中，Novel Platform 不接收、不保存、不回显。

### 6.2 v0.9 范围

只交付：

- 当前可读、`ready`、带当前 TXT 文件的 source Edition。
- 固定 `novel_txt_v1` 的整本异步翻译。
- 管理员或 translate 用户发起、查看、暂停、继续、取消、retry 和 retranslate 自己的任务。
- 管理员查看和控制全部任务。
- 完整成功后创建 TXT AI translation Edition，初始 `draft`。
- Draft 仅创建者和管理员可见；只有管理员能改为 `ready`。
- 页面关闭不取消 Job；返回后按需同步。

不做 EPUB/漫画/单段翻译、逐段校对、术语库、翻译记忆、Prompt UI、浏览器直连、SSE、
WebSocket、Redis、Celery、第二套 Job Runner、Provider Key UI、自动发布/首选/归档或常驻
reconciler。EPUB/无文件原文只显示明确限制。

### 6.3 翻译和重翻权限

- translate 用户可翻译任意自己当前可读的 ready TXT source，不要求也是原文上传者；
  Run 和生成结果归发起 User。
- 受邀人只管理自己的 Run，管理员管理全部。
- 受邀人 retranslate 时，`supersedes_edition_id` 只能是自己创建的生成译本；管理员可选
  同 Book、同 source 的任意 translation Edition。
- Retry 在同一 Run 内调用远端 retry，不创建第二个本地 Edition。
- Retranslate 创建新 Run 和新 draft；旧译本、文件、状态、首选和进度不变。
- 创建者可用安全 Reader Projection 预览自己的 draft；其他受邀人不可见。管理员审核
  ready 后才进入共享 readable 边界。

## 七、Translation Run、客户端和恢复

### 7.1 持久化

新增 `EditionTranslationRunModel` / `edition_translation_runs`，随 v0.9 下一 migration 创建。

至少包含：

| 字段 | 要求 |
| --- | --- |
| id | UUID 主键 |
| library_owner_user_id | 唯一管理员馆藏 owner |
| created_by_user_id | 实际发起 User |
| book_id/source_edition_id | 同 Book，source Edition |
| source_edition_file_id/revision/sha256/format | 固定输入快照；v0.9 format=txt |
| target_language/edition_title/supersedes_edition_id | 输出语义 |
| configuration_fingerprint/snapshot | 版本化、非秘密配置 |
| client_request_id | 按 actor + UUID 唯一 |
| remote_project_id/job_id/artifact_id/request_id/status | 可恢复远端关联 |
| status/progress | 本地状态与 0..1 进度 |
| generated_edition_id | 可空且唯一 |
| error_code/message/details | 脱敏错误 |
| retry_count/cleanup_status/cleanup_error | 重试与精确清理 |
| timestamps | created/updated/started/completed/last_synced |

状态至少为：

~~~text
preparing
queued
running
paused
cancelling
cancelled
partially_succeeded
failed
ingesting
succeeded
attention_required
~~~

要求：

- `succeeded` 表示本地 Edition 已原子提交；partial 不导入。
- `attention_required` 表示远端结果不确定、协议不兼容或需人工处理。
- generated Edition 已存在时同步重放返回原对象。
- 对输入文件 + 目标语言 + 配置指纹建立活动状态部分唯一索引；终态后允许 retranslate。
- client request ID 防浏览器重试；不同 User 的同 UUID 不冲突。
- remote Project/Job/Artifact 与 generated Edition 非空时唯一。
- Run 固定启动时的 EditionFile；后续 replace 不改变输入。
- 活动 Run 阻止删除来源 Edition/文件修订。
- 状态转换只存在于 domain/application 层。

### 7.2 窄契约客户端

新增强类型 `LinguaSpindleClient`：

- Base URL 只来自服务端配置，默认 `http://linguaspindle:8765`。
- 禁止用户 URL、重定向和跨 origin Artifact URL；只拼预定义路径并校验远端 ID。
- 使用 `httpx.AsyncClient`，将 httpx 纳入 Server runtime 依赖。
- 上传/下载流式处理，配置 connect/read timeout 与不高于本地 import 上限的下载限制。
- 只解析所需字段；远端错误映射为稳定、脱敏本地错误。
- 传递安全 `X-Request-ID`；不记录正文、multipart 或 Artifact 内容。

启动前检查版本 `>=0.3.1,<0.4.0`、health、强制幂等、`novel_txt_v1` 和配置 Provider。
LinguaSpindle 不可用时只禁用翻译，主站 readiness、登录、书库、上传和 Reader 正常。

### 7.3 发起、同步和幂等

1. 检查 admin/translate 和 source readable。
2. 锁定 source/current file，固定 revision、SHA-256、语言、actor、配置指纹。
3. 验证 retranslate 的 supersedes 规则。
4. 先提交本地 `preparing` Run，再进行远端 HTTP；长调用不持有 DB transaction。
5. 流式创建 Project，再创建 `novel_txt_v1` Job，保存安全关联 ID。

外部 Key 确定性派生：

~~~text
np:{run_id}:project:v1
np:{run_id}:job:v1
np:{run_id}:retry:{retry_count}:v1
~~~

同阶段重试复用 Key。进程在远端成功、本地保存前退出时，重放取回同一资源。

- GET 列表不产生远端写；显式 POST sync 才推进和导入。
- Web 只轮询可见活动 Run；页面隐藏/卸载/终态停止。
- Sync 用行锁保证只有一个终态导入者。
- 控制/清理检查 admin 或 Run creator + 当前 translate 能力。
- 网络超时不直接标记 failed；进入可恢复状态后查询/重放。
- 清理只能使用 Run 精确 Project ID，禁止名称/时间/通配符。

### 7.4 成功 Artifact 原子导入

仅远端 Job 完整 succeeded：

1. 选择唯一 `novel_export_txt`。
2. 验证 Project/Job/Artifact、media type、文件名、大小、SHA-256 和 download origin/path。
3. 流式写 temporary，重新计算大小/哈希并复用 TXT 校验与规范化。
4. 复用内部原子发布服务，不调用公开 upload API，不伪造 uploaded Import。
5. 单事务创建 StoredFiles、BookEdition、EditionFile 并更新 Run；文件/DB 失败完整补偿。
6. StoredFile owner 仍为 library owner；StoredFile/Edition creator 均为 Run creator。

生成 Edition 固定：

~~~text
content_role = translation
translation_origin = ai
creation_method = generated
source_edition_id = Run.source_edition_id
supersedes_edition_id = Run.supersedes_edition_id
status = draft
revision = 1
created_by_user_id = Run.created_by_user_id
~~~

禁止自动 preferred、归档旧译本、partial 导入或替换来源文件。成功后远端清理失败不回滚
Edition，记录 pending/failed 并允许授权 actor 精确重试。

## 八、HTTP API 与 Quiet Trace Web

### 8.1 API

- `UserResponse`/`MeResponse` 增加当前会话有效 `capabilities`；管理员返回完整规范集，
  Recovery Session 无馆藏能力。
- Admin Reader DTO、create、reissue 增加 capabilities；raw credential 继续 no-store 且只显一次。
- Imports 改为 capability + actor 隔离；Book/Edition patch/replace/delete 改为资源 policy。
- Book/Edition 响应增加安全 contributor 和 permission flags。
- 移除 metadata-only create schema/routes。

Translation API：

| 路径 | 权限 |
| --- | --- |
| `GET /api/v1/translation-service/status` | admin 或 translate |
| `POST /api/v1/books/{book_id}/editions/{source_id}/translation-runs` | admin 或 translate |
| `GET /api/v1/translation-runs` | admin 全部；受邀人仅自己的 |
| `GET /api/v1/translation-runs/{id}` | admin 或 creator |
| `POST /api/v1/translation-runs/{id}/sync` | admin 或 creator |
| `POST .../{id}/pause|resume|cancel|retry|cleanup` | admin 或 creator |

创建请求只接受目标语言、输出标题、可选 supersedes 和 client request UUID。浏览器不得提交
Provider Key、LinguaSpindle URL、Provider/Profile/Pipeline、模型参数或任意下载 URL。

变更后运行 `pnpm api:generate` 并提交确定性 OpenAPI 与 `schema.d.ts`。

### 8.2 签发和导航

### 8.3 书库、上传和删除

- 删除两个 legacy Collapse。
- 书库卡片和 Book 详情以安静次要文本显示“上传人：显示名称”。

### 8.4 翻译界面

- `can_translate` 的 TXT source 显示“翻译小说”。
- 自己的生成译本显示“重新翻译”；管理员可对所有符合规则的译本操作。

- Succeeded 对 creator 显示“预览草稿”；仅 admin 显示“审核并发布”，不能称 draft 已发布。
- 只轮询活动任务，页面可见时 3–5 秒、错误退避、隐藏/卸载/终态停止，同 Run 单 flight。

### 8.5 设计系统

使用 repository-local `novel-platform-design-system`：中文 accessible name、可见焦点、44 px
桌面/46 px 触控、320 px、移动 Drawer、`aria-live`、reduced motion；不使用第二组件库、
`transition: all`、全局 `!important` 或 Ant Design 内部 class。

## 十、测试与验收

### 10.1 能力和归属

必须覆盖：

- 旧凭证迁移后只有 read；create/reissue 正确持久化全部合法组合。
- 缺少 read、未知/重复 capability 拒绝；ReaderPatch 不能改 capability。
- Reissue 立即撤销旧 credential/device/session/refresh。
- Credential 轮换后 creator 仍是同一 User。
- JWT/前端伪造权限无效；Recovery Session 写接口全部 403。
- 审计只有安全 capability 名，不含 raw credential/正文。

至少使用 admin、read-only A、upload B、translate C、combined D：

- A 只读，写接口 403。
- B 能文件型 create/add/replace 自己内容，不能翻译。
- C 能翻译可读 TXT，不能上传任意文件。
- D 有并集，但不能改 B/C 的资源。
- Book/Edition/File/Import/Run actor 与唯一 library owner 同时正确。
- Book/Edition 安全显示上传人/翻译发起人。
- B 只能删自己的上传 Edition；C 只能删自己的生成 Edition；admin 可管理全部。
- B 的 Book 含 C 贡献时，B 整本删除 409。
- 依赖、活动 Run/Import 阻止删除。
- 删除 ready Edition 清理所有用户 preference/progress 和未引用文件。
- 无孤儿 DB/temporary/physical file，无路径泄漏。
- 非自己的 private Import/Run 404；可见资源越权写 403。

### 10.2 旧功能移除

- 两个 legacy Collapse 不存在。
- Web bundle/client/OpenAPI 无 metadata-only create。
- 旧 POST 404/405，不能创建无文件行。
- Migration 只删除占位，保留合法文件型 Edition 的 ID、revision、preference、progress。
- Migration report 只含计数，不含标题、文件名、路径、正文。

### 10.3 Lingua 与 Translation Run

- Version/capability/Provider 检查；窄 DTO；确定性 Idempotency/X-Request-ID。
- Streaming 上限、checksum、redirect、跨 origin、400/409/413/428/429/5xx/timeout/invalid JSON。
- 日志/错误不含正文、Provider Key、multipart 或 Artifact。
- Admin 管理全部；translate 只管理自己的；read/upload-only 403。
- 非 ready/source/TXT、无文件、跨 Book、非法 supersedes 拒绝。
- 受邀人不能 supersede 他人的 generated Edition；admin 可以。
- 来源 revision 固定；同 actor + client UUID 幂等；并发等价创建只有一个活动 Run。
- 远端响应丢失后同 Key 恢复；pause/resume/cancel/retry 状态正确。
- partial/failed 或 Artifact ID/size/checksum/format 错误不创建 Edition。
- 文件/DB 故障无孤儿；并发 sync 只生成一个 Edition。
- 结果是 draft + ai + generated + source + actor；creator/admin 可见，其他人不可见。
- Admin ready 后所有 reader 可见；retranslate 保留旧 Edition/文件/首选/进度。
- Cleanup failure 不回滚 Edition，只能精确 Project ID 重试。

### 10.4 Web 和 acceptance

- 签发/reissue 权限选择、摘要与失效提示。
- 四种身份的 AppShell、routes、buttons 投影。
- 安全 attribution，无内部 ID/hint 泄漏。
- Permission false 不显示操作；直接 API 仍拒绝。
- 删除冲突与后果文案。
- TXT 翻译、EPUB 限制、各状态控制、draft preview/admin publish。
- Polling visibility/backoff/unmount/single-flight。
- 320 px、移动 Drawer、键盘、焦点、reduced motion。

新增 `scripts/acceptance-v090.mjs`，完成后让 `pnpm acceptance` 指向 v0.9。历史证据不改；
v0.9 以当前产品契约建立门禁，至少覆盖：

2. Capability 签发、reissue、即时失效和 API 矩阵。
3. 四身份上传、归属、显示、删除与跨贡献者冲突。
4. Legacy UI/API 删除和占位迁移。
5. 私网 Project/Job 幂等、同步、控制和原子导入。
